# Переход Parser News на GPT-6 Luna

## Цель и выбор модели

Основной кандидат — `gpt-6-luna`, режим `none`: фактическое саммари, вопросы и
авторская переработка остаются на одной модели, с прежними промптами и Chat
Completions. Это небольшой первый шаг миграции; качество проверяется отдельно.

Официальные источники, проверены 05.10.2026:

- [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna): модель
  для массовых задач, поддерживает `none`; без явного усилия используется `medium`.
- [Миграция GPT-6](https://developers.openai.com/api/docs/guides/latest-model):
  сохранять роль модели и эффективное усилие; исключать `temperature` при reasoning
  выше `none`; оценивать качество перед изменением промптов и возможностей.

Luna выбрана по характеру нагрузки проекта, а не по результатам еще не проведенных
живых evals. Sol/Astra не включаются автоматически. Аудио, обложки, модерация,
публикация, Google Sheets и Telegram остаются в своих существующих контурах.

## Атомарный план и зависимости

1. Сначала отдельное исправление `fix/nlp-source-context` / PR #9: не генерировать
   факты по одному URL; адресно обрабатывать выбранный ID; не публиковать старое
   неподтвержденное саммари. Подмена исходного контекста не лечится сменой модели.
2. Данный PR `feature/gpt6-luna-text`: добавить совместимые параметры,
   ограничение ответа и времени, проверки ошибок и инструмент сравнения.
   База — опубликованная `feat/blog-editorial-media-pipeline` (`7fdc81b`);
   пять неопубликованных локальных коммитов не включены.
   Непосредственная база PR — `fix/publication-retry-exception` (`0ff5a09`, PR #10):
   отдельное исправление общей проверки публикации, выявленное GitHub CI.
3. На 100–200 реальных материалов сравнить `gpt-4o-mini` с Luna `none` при
   одинаковых промптах. Проверить источники до запуска, затем оценить результаты
   человеком. Эксперимент `low` выполнять отдельным запуском.
4. После приемки включить Luna в тестовом контуре; проверить полный цикл
   сбор → NLP → карточка → комментарий → адресная перегенерация → публикация
   в тестовый канал. Условия публикации и утверждения владельцем сохраняются.
5. Включить конфигурацию рабочего сервиса, сначала обработать небольшую новую
   очередь и проверить факты; затем продолжить обычную обработку. Старые записи
   не перегенерировать массово. При регрессии вернуть прежний `TEXT_MODEL`.
6. Responses API, извлечение текста статей по ссылке, структурированный формат
   вопросов и отдельная модель сложного rewrite — последующие независимые PR,
   после измерения первого шага. Docker Compose не меняется в этом PR.

## Изменения

- `config/settings.py`: явная настройка усилия, лимита токенов, времени и повторов.
  По умолчанию остается `gpt-4o-mini`, новая модель включается через `TEXT_MODEL`.
- `nlp/openai_client.py`: Luna получает `reasoning_effort`; `temperature=0.2`
  сохраняется для Luna `none` и прежней модели, исключается при `low` и выше.
  `max_completion_tokens` ограничивает видимый ответ вместе с reasoning.
- Для всех текстовых задач общий бюджет — 90 секунд, включая SDK-повторы;
  максимум один повтор по умолчанию. Аудио/медиа не получают эти настройки.
- `finish_reason != stop`, отказ, пустой ответ и отсутствие choices приводят к
  ошибке. Обрезанный текст не сохраняется как успешная генерация; существующий
  NLP-конвейер оставляет ошибку для разбора. Автоматической смены модели нет.
- Метрики записываются через существующий logger: модель, усилие, время,
  входные/выходные/reasoning/кэшированные токены. Тексты и ключи не логируются.
- `requirements.txt`: минимум SDK `1.109.1`, верхняя граница `<3`; старый `0.27`
  не поддерживает используемый уже до миграции `AsyncOpenAI`. Остальные
  зависимости и инфраструктурные файлы не изменены.
- `.env.example`: настройки кандидата и rollback.
- `scripts/evaluate_text_models.py`: одинаковые вызовы summary/questions/rewrite
  для двух моделей; JSONL-результат и метрики; по умолчанию только проверка входа.
  Рабочая БД не открывается и не изменяется, отправок в Telegram/Sheets нет.
- `tests/test_gpt6_text_migration.py`, `tests/test_text_model_eval.py` и CI:
  запросы реального SDK через MockTransport, все текстовые роли, несовместимые
  параметры, отказ/обрезка, 429, предел времени и проверка корпуса до API.

Это smoke-пример для проверки входа, не представительный набор оценки модели и
не текст для восстановления рабочей записи.

До постановки на PR #10 обязательный набор CI прошел локально: 123 passed.
26 профильных сценариев также прошли в Linux с реальным SDK и MockTransport
при read-only монтировании рабочего кода в ранее собранное окружение Docker.
Это не живые API-evals и не утверждение о выпуске. Финальные проверки новой
базы: GitHub CI — 124 passed; полный набор ветки в Linux — 124 passed.
Объединение с исправлением контекста прошло 146 тестов в Docker, merge-конфликтов

Docker-тестовый образ миграции собран поверх окружения, полученного существующим
Dockerfile исправления контекста; `pip install -r requirements.txt` проверил
обновленный диапазон SDK (установлен OpenAI 2.28.0), затем добавлены pytest-пакеты.
Это проверка сборки тестового образа с переиспользованием зависимостей, а не
вторая чистая сборка production-Dockerfile. Image ID тестового образа:
`sha256:ab91ec879f4fad6e4609c64b29de728004c1c51710bc08079d07f3adadefaba7`.
Для объединенной проверки использован точный Git-снимок дерева
`e45ef00498e18bb0438da69b4ed9c9ced0604811` (`1294003` + `73c5350`), тестовый image ID:
`sha256:e9d1ea38d911e7c4b3fa4e8c0c6f9586abcfb40cbaf619062b1dba4a4db15cdd`.
Контейнеры удалены после проверок; токены, рабочая БД и порты не подключались.

Каждая строка реального корпуса: `id`, `source_text`; опционально `owner_notes`,
`expected_facts`, `forbidden_facts` (строки). ID уникальны; пустой текст и URL без
содержимого отвергаются. Включить русские/английские новости, длинный текст,
расшифровки, числа и даты, технические материалы, похожие соседние новости,
перенос/отмену событий и авторские комментарии. Для ошибки Wakeflot ожидаемая тема
— консервация PCM; чемпионат Москвы 2023 запрещен. Исходник должен быть полным и
проверенным, а не только названием или короткой ссылкой.

Сначала dry-run, затем платные API-вызовы при наличии ключа и доступного проекта:

```powershell
python scripts/evaluate_text_models.py --cases C:\path\news-eval.jsonl
python scripts/evaluate_text_models.py --cases C:\path\news-eval.jsonl --output C:\path\luna-none-results.jsonl --run
python scripts/evaluate_text_models.py --cases C:\path\news-eval.jsonl --output C:\path\luna-low-results.jsonl --effort low --run
```

Результаты содержат тексты корпуса; хранить локально с доступом редакторов,
не коммитить и не публиковать. Existing output не перезаписывается. Ошибки
сохраняются по типу исключения; ненулевой exit при сбое любой пары case/model.
Статус человеческой оценки остается `null`, программа не объявляет качество
пройденным по наличию HTTP 200 или ключевых слов.

Предлагаемые условия приемки:

- Нет смешивания новостей, выдуманных существенных фактов, чисел или дат.
- Каждое существенное утверждение можно подтвердить исходником; при недостатке
  исходных данных ручное review. Возврат на русском, авторский комментарий сохранен.
- Доля принятых редактором результатов не ниже baseline; оценить все пары.
- Зафиксировать ошибки и p50/p95 задержки; нет нарушений 90-секундного бюджета.
- Сравнить расход и стоимость на принятый результат по актуальному тарифу проекта;
  отсутствующие usage-поля считать неизвестными, а не нулевыми.

## Docker, выпуск и риски

PowerShell, сборка существующим Dockerfile; контейнер только тестовый, без .env,
боевой БД, портов и стандартного запуска бота:

```powershell
docker build --tag mywave-parser-news:gpt6-luna .
docker run --rm --entrypoint sh mywave-parser-news:gpt6-luna -c 'python -m pip install pytest pytest-asyncio && python -m pytest tests/test_gpt6_text_migration.py tests/test_text_model_eval.py tests/test_openai_skip_moderation.py tests/test_openai_client.py::test_author_rewrite_uses_original_text_and_notes -q --tb=short -o asyncio_default_fixture_loop_scope=function'
```

Перед выпуском проверить CI именно финального SHA, SDK и доступ к Luna в реальном
OpenAI-проекте, настройки EU-маршрута и применимость data residency. Наличие EU
прокси само по себе не означает EU data residency. Сохранить конфигурацию и
резервную копию SQLite; подтвердить фактический путь/версию работающего сервиса.

Для включения задать в .env рабочего тестового/затем боевого сервиса:

```dotenv
TEXT_MODEL=gpt-6-luna
TEXT_REASONING_EFFORT=none
TEXT_MAX_COMPLETION_TOKENS=1600
TEXT_TIMEOUT_SECONDS=90
TEXT_MAX_RETRIES=1
```

Опасность: 1600 токенов может не хватить для длинного rewrite или reasoning `low`;
сначала проверить корпус, при необходимости изменить лимит осознанно. Таймаут и
выходные пределы также применяются к baseline. Доступ к модели/региональные ошибки
не маскируются сменой модели. Новая модель не решает ошибки сбора исходного текста.

Rollback модели: вернуть прежнее значение `TEXT_MODEL` и прежние настройки,
перезапустить сервис в подтвержденном контуре. Rollback кода: прежний проверенный
SHA/образ. Миграции БД нет; сохраненные результаты автоматически не откатываются
и должны пройти ревью. Если использовался `low`, восстановить также `none`.

Локально нет API-ключа и реального корпуса (локальная таблица items пуста).
SSH-проверка сервера завершилась таймаутом до аутентификации. Реальное качество,
доступность API, Telegram E2E и выпуск на сервер не подтверждены.

До изменений уже падали три теста `tests/test_openai_client.py`: строго русский
промпт, перевод английского ответа и fallback транскрипции. Поведение этих функций
в данном PR сохранено; это отдельные существующие проблемы. Обязательный CI-набор
не равен всему дереву тестов; результаты следует читать с этой оговоркой.
