# Саммари без текста источника: исправление

## Цель и подтвержденные данные

В скриншотах карточки Wakeflot #3048 исходный текст содержит только
`https://wakeflot.ru/news/1785`, а саммари описывает чемпионат России по вейкборду
14 октября 2023 года. По указанной ссылке опубликована статья
«Консервация и зимнее хранение двигателей PCM» от 22.09.2026.

Источник: https://wakeflot.ru/news/1785

В локальной SQLite запись этого поста не обнаружена. Поэтому установлен дефект
локального кода и воспроизведен его сценарий; происхождение конкретного серверного
саммари по журналу рабочего бота пока не проверено.

## План и изменения

1. Запретить фактическую генерацию по одному URL или заголовку без содержимого.
2. Скрыть старое неподтвержденное саммари и производный финальный текст при ревью.
3. Не превращать такое саммари в готовый пост при добавлении комментария или
   нажатии «Переписать»; существующая проверка публикации использует ту же защиту.
4. Перегенерировать только выбранные ID, не выбирая первый материал общей очереди.
5. Проверить временную SQLite, карточку и публикацию с заглушками внешних API;
   подключить регрессии к CI.

Ветка: `fix/nlp-source-context`. Исследование и первые проверки выполнялись на
`e729fdb`; PR перенесен на опубликованную базу `7fdc81b`
(`feat/blog-editorial-media-pipeline`) без пяти неопубликованных коммитов.
Единственный конфликт разрешен с сохранением подписи «Саммари (NLP)» из базы.
Затем PR поставлен поверх `fix/publication-retry-exception` (`0ff5a09`, PR #10):

исключения и платформенного ожидания пути вынесено в эту отдельную зависимость.
В диффе данного PR путь теста публикации больше не меняется.

Измененные файлы:

- `services/nlp_pipeline.py`: общий обработчик конкретных записей, ручное review
  при отсутствии исходного текста, адресная перегенерация.
- `utils/item_context.py`: URL без текста не считается контекстом; старая генерация
  по ссылке и результат с `source_context_missing` считаются неподтвержденными.
- `utils/owner_content.py`: неподтвержденное саммари не используется для финального
  поста автоматически.
- `telegram_bot/views.py`: скрытие неподтвержденного саммари/финального текста и
  блокировка кнопки переписывания без текста источника.
- `tests/test_item_context.py`, `tests/test_nlp_source_context.py`: регрессии
  отсутствующего текста, смешивания очереди, ревью, переписывания и публикации.
- `tests/test_publication_service.py`: ожидание пути обложки вычисляется через
  `Path`, вместо Windows-разделителя; это исправляет тест на Linux без изменения
  логики отправки обложки.
- `.github/workflows/ci.yml`: новые регрессии включены в обязательный тестовый шаг.

Текст с настоящим содержимым и ссылкой сохраняется. При URL в `content` и реальной
расшифровке в `transcript` используется расшифровка. Авторские комментарии выбранного
материала сохраняются. Явно отмеченная ранее авторская правка сохраняет прежний
контракт; эта отметка не является независимой проверкой достоверности.

## Docker

Сборка использует существующий Dockerfile; Dockerfile и зависимости не изменены.
Тестовый контейнер должен запускаться через переопределенный entrypoint, без
токенов, боевой БД, публикации портов и запуска бота.

```powershell

docker run --rm --entrypoint sh mywave-parser-news:nlp-source-context -c 'python -m pip install pytest pytest-asyncio && python -m pytest tests/test_nlp_source_context.py tests/test_item_context.py tests/test_owner_content.py tests/test_publication_service.py tests/test_owner_review_telegram.py tests/test_nlp_pipeline_fallback.py::test_process_nlp_skips_title_only_context_and_sends_to_review tests/test_nlp_pipeline_fallback.py::test_process_nlp_keeps_transient_errors_in_error_status -q --tb=short --disable-warnings -o asyncio_default_fixture_loop_scope=function'
```

Результат Docker: сборка финального рабочего кода завершилась с exit 0. Config SHA
образа: `0b4e15700c2c9b8044c7f122f8344edacccd50b455f586a557c210d443fb4d9d`.
В контейнере 65 сценариев прошли, один существующий тест обложки упал из-за

Таким образом, все 66 выбранных сценариев проверены; это не один полный повторный
запуск набора после правки ожидания пути. Команды выше собирают текущий тест вместе
с образом для воспроизведения всего набора.

## Риски, rollback и проверка перед деплоем

- Материалы без реального текста останутся на ручном review. Получение текста
  статьи по ссылке — отдельный следующий шаг; модель не читает URL автоматически.
- Защита отсутствующего контекста не проверяет семантическое соответствие любой
  произвольной пары полного исходника и саммари.
- В локальном окружении нет .env и настроенных ключей OpenAI/Telegram/Sheets.
  Реальные внешние интеграции, сервер и рабочая карточка не изменялись.
- Схема БД не меняется. Rollback: вернуть предыдущий проверенный SHA/образ и
  конфигурацию сервиса. Не запускать массовую перегенерацию.

Перед выпуском через отдельный PR: дождаться CI; сохранить резервную копию рабочей
SQLite; найти запись по Telegram URL, а не считать #3048 внутренним ID БД; проверить
ее `content`, `transcript`, `nlp_results.extra.sanitized_text` и журнал обработки;
проверить в тестовом канале карточку без текста и адресную перегенерацию при наличии
других элементов `new`.

После выпуска сначала восстановить реальный текст только для проблемной записи,
затем перегенерировать именно ее и проверить соответствие фактов источнику.
Этот сценарий включить в обязательную оценку перед переходом на GPT-6.
