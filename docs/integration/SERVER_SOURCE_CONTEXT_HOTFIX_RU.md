# Точечный серверный hotfix для записи 649

Серверная проверка установила ID записи Wakeflot: `649`. В `content` находится
только ссылка на статью PCM, а старый результат NLP описывает чемпионат 2023 года.
Бот работает в `/opt/bot3/parser-new-bot`, unit — `parser-news-bot`.

Семь присланных raw Git blob совпали с файлами локальной версии `e729fdb`
после учёта CRLF у `services/nlp_pipeline.py`, `telegram_bot/views.py`,
`utils/owner_content.py`, `storage/repository.py`. Остальные три файла имеют LF.
Это объясняет отказ обычного `git apply --check`. Серверный Git checkout
остался на `06fcfb4`; локальные серверные изменения нельзя заменять checkout ветки.

## Порядок выполнения

`scripts/apply_source_context_hotfix.py` по умолчанию проверяет применимость.
Опция `--apply` выполняет уже проверенный точечный rollout:

1. Проверить семь raw blob, unit/WorkingDirectory, DB_PATH и сохранённую модель
   `gpt-4o-mini`. Проверить, что запись 649 всё ещё в review с URL без transcript.
2. Получить diff четырёх runtime-файлов между опубликованными `0ff5a09` и
   `826cf72`. Применить его в отдельном временном каталоге с LF, сохранив
   название карточки «Кратко (факты)», затем вернуть каждому файлу его CRLF/LF.
3. Сохранить исходные байты файлов, manifest и копию скрипта в приватный каталог
   `/opt/bot3/backups/source-context-649-*`. Остановить только указанный unit
   и сделать согласованный SQLite backup через SQLite backup API.
4. Атомарно заменить четыре файла с сохранением mode/uid/gid. Проверить их
   отпечатки, отсутствие контекста у URL и скрытие ложного текста в карточке.
5. В одной SQLite-транзакции заменить только производный NLP-результат 649
   предупреждением об отсутствии источника. Сохранить комментарий, голос,
   обложку и исходные items; удалить старые производные переводы и merged_text.
6. Запустить unit и проверить active/PID в течение восьми секунд. Напечатать
   результат и точную команду отката кода из сохранённого backup.

Скрипт не вызывает OpenAI, не запускает второй polling-процесс, не меняет
настройки, зависимости, Git checkout или инфраструктуру других сервисов.
Текст статьи не импортируется: материал остаётся на ручном ревью до получения
содержимого выбранного источника и новой адресной генерации.

### Если статус записи уже изменился

`--apply --code-only` устанавливает те же четыре runtime-файла независимо от
статуса записи 649. Проверки отпечатков, настройки, staging, backup кода/SQLite,
smoke и восстановление сервиса сохраняются. Скрипт не проверяет и не изменяет
производный результат 649; успешный ответ содержит `data_repair=skipped` и
не утверждает, что запись находится в review. Её актуальный статус и наличие
публикаций нужно прочитать отдельно перед исправлением данных.

Предварительные отказы теперь выводят безопасный код проверки, например
`target_status_changed` или `server_file_changed:services/nlp_pipeline.py`.
Тексты произвольных исключений с возможными секретами не выводятся.

## Проверка

```bash
python -m pytest -q tests/test_source_context_hotfix.py
python -m ruff check scripts/apply_source_context_hotfix.py tests/test_source_context_hotfix.py --select E9,F63,F7,F82
```

Тесты проверяют CRLF/LF, staging без изменения исходников, замену/возврат точных
байтов, отказ при изменённом файле/источнике и сохранение соседней записи,
комментария, голоса и обложки. Отдельный Docker-прогон использует снимок
проверенных серверных исходников и профильные регрессии source-context.

## Ограничения и откат

Остановка unit создаёт короткий перерыв обслуживания. Любое расхождение
отпечатков или source/status завершает проверку до применения. При ошибке
после остановки скрипт возвращает исходный код и запускает unit.

Уже выполненное безопасное удаление ложного результата 649 сохраняется при
откате. Рабочая SQLite не заменяется целиком, поэтому последующие данные бота
сохраняются. Полный DB backup остаётся для отдельного восстановления при
необходимости. Ручной `--rollback-code` отказывается перезаписывать код,
изменённый после этого rollout.

Стабильный PID и smoke карточки подтверждают локальный запуск и защиту текста.
После rollout нужно открыть `/item 649` в действующем Telegram-боте и проверить
карточку. Доставка Telegram и качество модели этим скриптом не измеряются.
