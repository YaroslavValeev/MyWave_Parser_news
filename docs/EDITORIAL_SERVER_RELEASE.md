# Серверное обновление редакционного NLP с gpt-4o-mini

Обновление включает извлечение текста статьи, привязку источника,
ограничения API, русский перевод, аудио fallback и исправление fallback
повторов публикации. Модель `gpt-4o-mini`, порты, systemd unit, nginx,
Docker Compose и Git checkout сохраняются.

## Почему нужен отдельный overlay

На сервере работают изменения от локального `e729fdb` и предыдущий
source-context hotfix. Публичная редакционная ветка не содержит всех
этих изменений. Полная замена файлов или checkout потеряли бы отправку
медиа, свежий порядок очереди, настройки обслуживания и существующую
обработку недоступной модерации. Поэтому release содержит контекстный
патч и хеши до/после для 11 файлов. Неизменяемые зависимости проверяются
отдельно. CRLF/LF и права существующих файлов сохраняются.

Функциональная база: PR #16, #17 и #18, коммит `30df7caf107086c217ceeb1fc50a48e0e9a93720`.
Серверный профиль проверен отдельно на копии кода от `e729fdb` с уже
установленной защитой источника. Локальные незакоммиченные клавиатуры
и пять прежних коммитов этим release не публикуются и не меняются.

## Порядок действий

Команды выполняются в Bash после SSH-входа, каталог
`/opt/bot3/parser-new-bot`, Python `venv/bin/python`.

1. Скачать `scripts/deploy_editorial_release.py` по точному SHA release
   и проверить SHA-256 установщика.
2. Запустить `--check --package-ref <полный SHA release>`. До остановки
   сервиса проверяются хеши, текущая модель, БД и статус 649; на временной
   копии применяется патч и выполняется полный сценарий с моками транспорта.
3. Для включения загрузки Wakeflot добавить аргументы
   `--enable-host wakeflot.ru --probe-url https://wakeflot.ru/news/1785`.
   Проверка скачивает только публичную статью, без OpenAI и Telegram.
4. После успешной проверки выполнить тот же вызов с `--apply`.
   Установщик повторяет проверки, сохраняет код, `.env` и консистентную
   копию SQLite в приватном `/opt/bot3/backups/editorial-release-*`,
   останавливает сервис, устанавливает патч, применяет nullable миграцию,
   выполняет сценарий с моками и перезапускает сервис.
5. Проверить JSON `release=ok`, стабильный MainPID и активный сервис.
   Публичные флаги добавляются в `.env`; модель и остальные параметры
   сохраняются. Запись 649 остаётся `discarded`, без публикаций.

`--check` не изменяет production-код/БД/конфигурацию и не перезапускает
бота. Все генерации и отправки проверочного сценария используют моки.
На действующем боте после включения флага новые подходящие ссылки
проходят обычный NLP и ручное одобрение владельцем.

## Проверка без отправки

`venv/bin/python -B scripts/editorial_offline_smoke.py` выполняет две
цепочки на временной SQLite: успешная редакционная публикация через
мок Telegram и отказ публикации при смене источника. Используется
реальный SDK с MockTransport. Настоящие сетевые транспорты блокируются.
JSON должен показать `real_telegram_sends=0`, `real_openai_requests=0`.
Этот тест не подтверждает права бота в живом канале.

## Откат

При сбое установки код восстанавливается автоматически и сервис
запускается с прежними файлами. Данные владельца не откатываются.
Колонка `source_context` остаётся nullable, старый код её игнорирует.
При включении загрузки автоматически откатываются только два публичных
флага; независимые изменения остальных параметров `.env` сохраняются.

Ручной откат: сохранённым проверенным установщиком выполнить
`--rollback-dir <каталог backup из JSON release=ok>` из каталога проекта.
Он сверяет текущий код и конфигурацию с сохранёнными хешами и прекращает
работу при новых правках, чтобы не затереть их. БД целиком не восстанавливается.

## Риски и ограничения

Неизвестное серверное изменение блокирует установку до записи файлов.
Нужно прислать вывод проверки, чтобы адаптировать следующий патч.
Проверки извлечения строгие: неподдерживаемая разметка или недоступный
сайт оставляют материал на ручном ревью. Старт сервиса подтверждается
активным состоянием и стабильным PID; последующее поведение в живом
Telegram канале требует отдельной проверки после решения владельца.
