Debugging tips
=================

1. Check environment variables in `.env` or OS env. Important keys: OPENAI_API_KEY, TELEGRAM_BOT_TOKEN, DB_PATH, CHANNEL_ID.
2. Run unit tests with pytest. Focus on repository and services first.
3. If aiogram/openai imports fail, install packages from `requirements.txt`.
% Руководство по отладке MyWave Parser

Этот файл описывает базовые шаги для диагностики проблем в проекте после перехода на новую архитектуру.

## 1. Проверка окружения
1. Скопируйте пример `.env.example` и заполните обязательные переменные (OpenAI, Telegram, расписание).
2. Убедитесь, что локальная база данных доступна по пути `DB_PATH`.
3. Активируйте виртуальное окружение и установите зависимости:
   ```bash
   python -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

## 2. Базовая диагностика
1. Выполните прогон тестов, чтобы убедиться, что база и сервисы работают:
   ```bash
   pytest
   ```
2. Для выборочной проверки подсистем запустите узкие тестовые наборы:
   ```bash
   pytest tests/test_repository.py
   pytest tests/test_nlp_pipeline.py
   pytest tests/test_publication_service.py
   ```

## 3. Проверка планировщика и бота
1. Для локальной отладки планировщика запустите `bot_aiogram.py` в режиме разработки:
   ```bash
   python bot_aiogram.py --debug
   ```
   Параметр `--debug` активирует расширенные логи и отключает APScheduler, чтобы можно было вручную вызывать задачи.
2. Используйте команду `/collect` в Telegram для точечного парсинга источников. Например:
   ```
   /collect https://example.com/feed.xml --type rss --period "2d"
   ```
   Результаты отображаются в ответе бота и логе `manual_collect`.

## 4. Анализ логов
1. Общая информация попадает в `parser.log` и `bot.log`.
2. Подробная информация по публикациям фиксируется в таблице `logs` БД; для анализа используйте любой SQLite-клиент:
   ```bash
   sqlite3 mywave.db 'SELECT * FROM logs ORDER BY created_at DESC LIMIT 20;'
   ```

## 5. Ручной запуск пайплайнов
1. Чтобы принудительно обработать очередь NLP:
   ```bash
   python -m services.nlp_pipeline --run-once
   ```
2. Чтобы выполнить повторную попытку публикаций:
   ```bash
   python -m services.publication --retry-once
   ```

## 6. Частые проблемы
| Симптом | Диагностика | Решение |
| --- | --- | --- |
| Пустые ответы OpenAI | Проверьте `OPENAI_API_KEY` и модель в `.env` | Обновите ключ или выберите доступную модель |
| Ошибки Telethon | Убедитесь, что учётные данные Telegram корректны | Повторно авторизуйте сессию через `start_telethon.py` |
| Ничего не сохраняется в БД | Проверьте путь `DB_PATH` и права доступа | Запустите миграции и убедитесь, что каталог существует |

## 7. Дополнительные советы
- Включайте `LOG_LEVEL=DEBUG` в `.env`, чтобы получить больше информации.
- Используйте `pytest -k <pattern>` для выборочного прогона тестов конкретных сценариев.
- При работе с aiogram включайте `AIROGRAM_LOG_LEVEL=DEBUG` для детальной диагностики событий.

## 8. Работа с удалённым репозиторием
Внутри песочницы нет доступа к сетевым удалённым репозиториям (GitHub, GitLab и т.п.), поэтому команды
`git fetch`, `git pull` и `git push` завершатся ошибкой подключения. Это ограничение среды, а не самого
проекта.

Чтобы опубликовать изменения во внешнем репозитории:

1. Скопируйте изменения из песочницы (например, через `git format-patch` или архив) на свою машину.
2. Настройте локальный `git remote add origin <ssh|https>` с нужным URL.
3. Выполните `git push` из окружения, где есть доступ к сети и права на репозиторий.

Альтернативный вариант — создать патч (`git diff > mywave.patch`) и применить его в локальном клоне проекта
командой `git apply mywave.patch`, после чего сделать коммит и отправить `git push` уже со своего компьютера.
