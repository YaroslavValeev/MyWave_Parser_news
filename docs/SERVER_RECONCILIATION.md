# Согласование GitHub и рабочего сервера

Модель остаётся `gpt-4o-mini`; живые тестовые отправки запрещены по решению
владельца. Новые работы собирают уже существующий серверный код с исправлениями
источника в одну проверяемую ветку, не заменяя файлы рабочего сервера.

## Изменения медиа и сбора

Функциональные изменения локальных коммитов `f6e29a2` и `e729fdb` перенесены
поверх опубликованного редакционного кода от `27d123a`. Они сохраняют:

- материализацию медиа, локальные файлы и fallback отправки;
- объединение Telegram-альбомов, общую подпись и восстановление медиа;
- RSS-изображения и отчёт о сборе, свежий порядок очереди;
- private-only обработку Owner-бота и настройки прокси.

При конфликте сохранены новые инструкции модели и блокировка неподтверждённых
фактов. Проверки `source_input_sha256`, `source_text_sha256` и статуса при
сохранении NLP остаются обязательными. Старые release manifest/patch сохраняются
неизменными: их SHA используются в уже выполненных серверных командах.

Клавиатура основного checkout совпадает с его HEAD по сырому Git blob;
содержательной незакоммиченной правки нет. Основной checkout сохраняется
до готовности и проверки опубликованной объединённой ветки.

## Отдельная операция обслуживания

Коммиты `dfb9382`, `38762c4`, `3d6e417` относятся к maintenance и PowerShell
развёртыванию. Они оформляются отдельно от медиа. Дублирующий workflow
`ci-p0-security.yml` не нужен: действующий CI уже сканирует текущее дерево и
историю. Дополнительные проверки медиа/альбомов включены в существующий CI.

## Проверки и оставшаяся граница

Обязательны существующий редакционный gate и тесты затронутых медиакомпонентов.
Docker запускается с `--network none`, временной SQLite и поддельными клиентами.
Проверка полного процесса в живом Telegram остаётся отложенной. Сначала сверить
серверные хеши и Git-состояние read-only командой; публикация или checkout
на сервере из этой работы автоматически не выполняются.

Финальная сверка сервера должна сохранить 626 на `review`, 649 на `discarded`,
контекст статьи, комментарии и медиа. Нельзя откатывать всю SQLite после новых
действий владельца. До серверной сверки совпадение полного рабочего дерева
с объединённой веткой не считается доказанным.
